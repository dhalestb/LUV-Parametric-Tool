# Lobby implementation transfer — review report

The isolated integration application now exposes **all 15 typologies** in Proto-Form Generation: five Gathering, five Workspace and the five requested Lobby names. Lobby generation reuses the developer's pinned Ruleset A and Ruleset B. It is not a saved-final substitution.

**Revision boundary:** live generation uses the coherent Git source at bf7fc3c8a9235fc3d4910b7b266821d484af93bf. The later ZIP finals retain their original saved meshes/configurations in the immutable reference namespace. The ZIP does not include its final source-lobby-envelope revision, so this implementation does not claim to reproduce that later final generator revision. No mixed ZIP/Git engine was assembled.

## Implementations and dependency map

All five types share the original source files; they are **not five independent solid-engine implementations**.

| Typology | Ruleset A | Ruleset B |
|---|---|---|
| Vertical Void Lobby | lobbyProof.ts → populateLobby('vertical-void-lobby', …), original sizing/pose/fit helpers | source-envelope.cjs → lobbyEnvelope in source-lobby-envelope.cjs; original source-profile dispatch |
| Compressed Sequential Lobby | lobbyProof.ts → populateLobby('compressed-sequential-lobby', …), original sizing/pose/fit helpers | source-envelope.cjs → lobbyEnvelope in source-lobby-envelope.cjs; original compressed dispatch |
| Continuous Hall Lobby | lobbyProof.ts → populateLobby('continuous-hall-lobby', …), original sizing/pose/fit helpers | source-envelope.cjs → lobbyEnvelope in source-lobby-envelope.cjs; original source-profile dispatch |
| Topographic Lobby | lobbyProof.ts → populateLobby('topographic-ground-field-lobby', …), original sizing/pose/fit helpers | source-envelope.cjs → lobbyEnvelope in source-lobby-envelope.cjs; original source-profile dispatch |
| Linear Gallery Lobby | lobbyProof.ts → populateLobby('linear-gallery-lobby', …), original sizing/pose/fit helpers | source-envelope.cjs → lobbyEnvelope in source-lobby-envelope.cjs; original source-profile dispatch |

~~~text
Unified selector
 ├─ preserved Gathering controller → private existing Gathering API/worker
 ├─ existing Workspace controller → unchanged existing API/worker
 └─ Lobby adapter
     ├─ Ruleset A: private pinned lobbyProof / letterGeometry3d
     └─ private POST → unchanged worker → buildSource → lobbyEnvelope
          ├─ private featurePoints / upperTriangles / profile helpers
          ├─ Three + Manifold packages already installed
          └─ unchanged full rule-validation (MeshBVH + crossings/coplanar checks)
               → new UUID → separate lobby-generated namespace

Approved ZIP finals → existing hash-verified immutable API → saved raw meshes
Current board renderer ← saved current result (no architectural regeneration)
~~~

The original glyph implementation differs from the application's shared glyph helpers, so it was copied privately. The profile/vertical helpers needed by Lobby were also pinned privately. The worker's TypeScript loader runs in a child process and cannot replace the application's runtime glyph module. Private packages include fallback/type dependencies for their original runtime closure; the Lobby endpoint forces proof='lobby', so other generator paths are not registered through it. UI-only Canvas/navigation/presentation helpers are reused from the current application where compatible.

The original fitLobbyLettersToArchitecture display post-process was transferred as source but is not applied to stored generated meshes or approved raw references. New studies are shown in their actual validated coordinates. Historical display fitting and the missing later ZIP engine remain separate parity questions.

## Remaining issues and limits

1. **Production build is not passing.** Initial sandboxed build failed on font-network/filesystem access. A separate-cache build with normal access failed in the existing Webpack WasmHash path (TypeError reading null.length). Prior readiness logs record the same tooling problem. No font, validation, TypeScript or build checks were disabled to obtain a pass. See build.log and build-review.log.
2. **Full TypeScript remains at 54 errors, unchanged from 54; no new errors.** Errors remain in the previously reported height-routing, sizing and evaluation code. The new adapter/controller graph adds no diagnostic. See typescript.log and preservation.json.
3. **Later ZIP live-generator parity is unresolved.** Its final source-lobby-envelope revision and final display-fitting environment were not supplied. Approved saved final fidelity is protected; live operation is verified for the explicitly pinned Git revision, not an invented reconstruction of that later revision.
4. Original deterministic Ruleset A does not supply a random seed variation for unchanged inputs. New Design creates a fresh original-rules run; use different valid input settings for a distinct geometry. Tested populations six and seven produce distinct meshes for every type.
5. This is a local, isolated review implementation. No commit, push, merge, deployment, source-worktree overwrite, reset, stash or discard was performed. Browser-based generation and board captures were observed before the browser connection became unavailable during the final recapture attempt; the saved screenshots/PNGs and server endpoints remain available for review.
